SkillLearn: Arsitektur, Alur Aplikasi, Keamanan & Deployment

Dokumen ini menjelaskan bagaimana SkillLearn dibangun dan diamankan: aplikasi web (React), aplikasi mobile (React Native/Expo), server API (Node.js/Express) dan database MongoDB. Semua layanan memakai paket gratis.

Desain UI dan prototype: SkillLearn UI.dc.html beserta halaman Web/Mobile. Referensi state: bagian STATES di kanvas.

1. Arsitektur sistem

Klien web dan mobile tidak pernah mengakses database secara langsung. Semua data lewat REST API Express yang memvalidasi input, memeriksa token, dan membatasi akses ke data milik pengguna sendiri. Web memanggil API lewat path /api di domain yang sama (rewrite/proxy), sehingga cookie refresh token tetap first-party.

4. Keamanan yang diimplementasikan

4.1 Authentication

KontrolImplementasi
Hash passwordargon2id (memory 19 MiB, iterations 2, parallelism 1, sesuai rekomendasi OWASP). Panjang password 8–128 karakter, minimal satu angka, ditolak jika termasuk daftar password umum.
Access tokenPASETO v4.public (Ed25519), berlaku 15 menit. Claim: sub, sid, role, iss, aud, iat, exp, jti. Footer berisi kid untuk rotasi kunci. Isinya terbaca (ditandatangani, bukan dienkripsi), jadi tidak memuat data sensitif.
Refresh tokenString acak 256-bit (bukan PASETO), disimpan di DB sebagai hash SHA-256. Dirotasi setiap dipakai; sliding 7 hari, absolut 30 hari.
Deteksi pencurian tokenJika refresh token lama dipakai lagi, seluruh keluarga sesi dicabut dan pengguna harus login ulang.
Penyimpanan di klienWeb: access token di memori, refresh token di cookie httpOnly + Secure + SameSite Strict + Path=/api/auth. Mobile: expo-secure-store. Tidak memakai localStorage atau AsyncStorage untuk token.
Anti user enumerationPesan login generik; register dan forgot password selalu 202; verifikasi terhadap hash dummy jika email tidak ada; rate limit per IP dan per email.
Verifikasi email & resetToken acak sekali pakai, disimpan sebagai hash, berlaku 24 jam (verifikasi) dan 30 menit (reset). Reset mencabut semua sesi.
LogoutSesi dicabut di server (revokedAt), cookie dihapus. Ada opsi "log out of all devices".

4.3 Authorization (anti-IDOR)

  • Identitas pengguna hanya diambil dari claim sub pada token yang sudah diverifikasi. API tidak pernah menerima userId dari body, query, atau path.
  • Data pribadi ada di bawah /api/me/…. Setiap query Mongo selalu menyertakan userId: req.user.id, sehingga satu pengguna tidak bisa membaca atau mengubah data pengguna lain dengan mengganti ID.
  • Resource milik orang lain dijawab 404, bukan 403, agar keberadaannya tidak bocor.
  • ObjectId divalidasi sebelum query (400 jika tidak valid). Role (student/admin) dicek dengan middleware requireRole untuk endpoint admin.
  • Anti mass-assignment: update profil hanya menerima field dari allowlist zod yang strict; field role, email, dan passwordHash tidak bisa diubah lewat PATCH /api/me.
  • Skor quiz dihitung di server dari kunci jawaban yang tidak pernah dikirim ke klien.

4.4 Injection & validasi input

AncamanMitigasi
NoSQL injectionSemua body, query, dan params divalidasi dengan skema zod strict (tipe string, bukan objek). Mongoose sanitizeFilter dan strictQuery aktif, jadi operator seperti $ne atau $gt dari input tidak dijalankan.
SQL injectionTidak relevan karena tidak ada database SQL. Query Mongo dibangun dari objek, bukan dari string yang digabung.
XSSReact dan React Native meng-escape teks secara default. dangerouslySetInnerHTML tidak dipakai. Isi artikel disimpan sebagai Markdown dan dirender dengan rehype-sanitize. CSP tanpa unsafe-inline/unsafe-eval menjadi lapisan kedua.
ReDoS di pencarianKata kunci dibatasi 60 karakter dan di-escape sebelum dipakai di $regex.

Kode 8. vercel.json: proxy /api ke Render (cookie jadi first-party) dan security headers. Nilai CSP lengkap ada di tabel header di atas.

  • CORS: hanya origin aplikasi web yang diizinkan, dengan credentials. Aplikasi mobile tidak terkena CORS dan memakai Bearer token.
  • CSRF: access token dikirim lewat header Authorization (bukan cookie), sehingga request lintas situs tidak membawanya. Satu-satunya endpoint yang memakai cookie (/api/auth/refresh) dilindungi oleh SameSite Strict, pengecekan header Origin, dan header wajib X-Requested-With.
  • HTTPS di semua jalur: Vercel, Render, dan Atlas memakai TLS; HSTS memaksa browser selalu memakai HTTPS.

4.6 Secrets, logging & perlindungan data

  • Secret hanya ada di environment variable Render. File .env masuk .gitignore. Variabel berawalan VITE_ atau EXPO_PUBLIC_ terlihat oleh klien, jadi tidak pernah berisi secret.
  • User database Atlas memakai hak minimum (readWrite di satu database). Render free tidak punya IP statis, jadi akses jaringan Atlas memakai 0.0.0.0/0 yang dikompensasi dengan password kuat dan TLS.
  • Log tidak pernah mencatat password, token, atau isi Authorization. Event keamanan (login gagal, reuse refresh token, reset password) dicatat dengan userId dan IP.
  • Dependensi dicek dengan npm audit dan Dependabot di GitHub.
  • Data pribadi yang disimpan dibatasi seperlunya (nama, email, bio, minat, riwayat belajar). Pengguna bisa mengubah profil dan meminta penghapusan akun, sejalan dengan prinsip UU No. 27 Tahun 2022 tentang Pelindungan Data Pribadi.

5. Deployment gratis

  1. MongoDB Atlas: buat cluster M0, buat database user khusus aplikasi, atur Network Access , lalu salin connection string ke MONGODB_URI.
  2. API di Render: New Web Service dari repo GitHub (folder server). Build npm ci, start node src/index.js, health check /api/health, isi environment variable dari Tabel 4.
  3. Web di Vercel: import repo (folder web, preset Vite), isi VITE_API_BASE=/api, commit vercel.json (Kode 8). Alternatif Cloudflare Pages: header di file _headers, proxy /api lewat Pages Function . Alternatif Firebase Hosting : header dan rewrite diatur di firebase.json.
  4. Mobile: npx expo start --tunnel untuk QR Expo Go, atau eas build -p android --profile preview untuk file APK.
  5. Email: akun Resend, verifikasi domain pengirim (atau pakai alamat uji untuk demo), simpan RESEND_API_KEY.
  6. Seed data: jalankan npm run seed untuk 8 course contoh dan 1 akun admin.
